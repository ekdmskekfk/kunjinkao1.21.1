# 覆写·断未「五主题异象」设计表

本文对应 `src/main/java/dev/modmind/kunjinkao/KunJinKaoTheme.java` 中的主题数据表，
并由 `overwrite/KunJinKaoOverwriteHandler.java`（服务端时序）与
`client/KunJinKaoClientOverwriteEffects.java`（客户端演出）消费。

## 总览

主题号 `0..4`，共 5 个。玩家手持管理员剑按 **P** 键循环切换，
当前主题持久化在物品 NBT 的 `OverwriteTheme` 字段中（`KunJinKaoSwordItem.getTheme/setTheme/cycleTheme`）。

每个主题由三段构成：

| 段 | 常量 | 含义 |
|---|---|---|
| 阶段一 | `PHASE_ONE` (0) | 进入覆写时的开场提示，单行 |
| 阶段二 | `PHASE_TWO` (1) | 逐行展开的日志滚动，是本主题的主体 |
| 阶段三 | `PHASE_THREE` (2) | 倒计时结束、执行「断未」前的裁决文字 |

另有结束语 `endText`，在目标被清除后显示。

**阶段二的行显示规则**（`stageTwoLinesVisible`）：第 `i` 行的累计间隔之和 ≤ 当前已过 tick 数时该行才出现，
即 `intervals[i]` 是「上一行出现后再等多少 tick 才出现本行」，行 0 立即显示。至少显示 1 行。

## 主题 0 — 命令行执行·逐级递归型

| 项 | 值 |
|---|---|
| 阶段配色 | 一 `#FFE0E0E0` / 二 `#FFE0E0E0` / 三 `#FFE53935` |
| 染色 tint | `[1.0, 1.0, 1.0]` |
| 服务端粒子 | `END_ROD` |

- **阶段一**：`> 正在加载"覆写·断未"...`
- **阶段二**（间隔 tick：0, 8, 8, 8, 8, 8）：
  1. `> 正在覆写目标属性...`
  2. `> 防御: 已覆盖 [原值 → 0]`
  3. `> 速度: 已覆盖 [原值 → -60%]`
  4. `> 增益状态: 已清空`
  5. `> 主手武器: 已替换为 [损坏的泥土]`
  6. `> 覆写完成。等待执行断未...`
- **阶段三**：`>>> 执行断未... 目标已标记为 [未定义] <<<`
- **结束语**：`> 执行完毕。共清除 1 个对象。`

| 项 | 值 |
|---|---|

- **结束语**：`> <目标名称> 已丢弃 (原因: 无法编译)`

## 主题 4 — 深度调试型

| 项 | 值 |
|---|---|
| 阶段配色 | 一 `#FF448AFF` / 二 `#FF448AFF` / 三 `#FF448AFF` |
| 染色 tint | `[0.3, 0.55, 1.0]`（偏蓝） |
| 服务端粒子 | `DustParticleOptions(0.25, 0.55, 1.0, 1.0)` |

- **阶段一**：`> 正在 <目标名称> 处设置断点...`
- **阶段二**（间隔 tick：0, 5, 5, 5, 5, 5）：
  1. `[DBG] 正在执行: <目标>.update()`
  2. `[DBG] 变量 "防御" = 0 (已覆写)`
  3. `[DBG] 变量 "速度" = -60% (已覆写)`
  4. `[DBG] 变量 "增益" = NULL (已清空)`
  5. `[DBG] 调用: <目标>.death_check()`
  6. `[DBG] 返回值: TRUE`
- **阶段三**：`[DBG] 检测到致命错误: 对象 "<目标>" 已无法修复`
- **结束语**：`> 调试完成。对象已释放。`

> 主题 4 同样会在覆写期间对目标 `setNoAi(true)` 并清零速度。
> 其粒子使用蓝色调色尘（Dust）而非 `ENTITY_EFFECT`，因为后者需要额外载荷，Dust 是安全等价实现。

## 文本占位符
